# Подготовка первой публикации

## Текущий статус

Публичный исходный выпуск BMS 1.0 размещается в
[bisembi/BMS](https://github.com/bisembi/BMS) с разрешения правообладателя.
Он имеет статус Pre-release; рабочее внедрение на новой инфраструктуре
требует отдельной приёмки.

Правообладатель: **Джабаев Бисемби**. Лицензионные тексты:
[LICENSE](../LICENSE.md), [NOTICE](../NOTICE.md),
[сторонние компоненты](../THIRD_PARTY_NOTICES.md).
Владелец утвердил BMS Community License 1.0: бесплатное внутреннее использование
компаниями и бесплатные форки с сохранением авторства и условий разрешены;
платная работа специалиста по установке, настройке и доработке разрешена.
Продажа BMS и платного доступа к её функциональности без отдельного разрешения
запрещена. Это source-available, а не MIT/Apache/GPL. Полный текст лицензии
определяет условия, краткое описание их не заменяет.

## В комплект включено

- Frontend с нейтральной темой, backend, SQL BMS, локальные обработчики и ограниченный setup.
- Одна исходная редакция без Git-истории, веток и тестовых проектов.
- Руководство с ролевыми разделами и синтетическими скриншотами.
- Архитектура, модель данных, каталог маршрутов, установка, эксплуатация,
  интеграция, ошибки, приёмка и известные ограничения.
- Манифест с хешами всех файлов и архив для переноса.

Приёмочные сценарии в документации — не исполняемые тестовые проекты.
Отказ от публикации тестов не означает отказ от проверки перед внедрением.

## Что нельзя включать

Рабочие БД и backup, .dt/.cf, SQL data/log, DPAPI/ключи/сертификаты с закрытым
ключом, production appsettings, SMTP-файлы, реальные профили адаптеров,
сотрудники/роли/бюджеты/платежи/контрагенты, первичка, почтовые выгрузки,
node_modules, bin/obj/dist, журналы, внутренние handoff и доказательства
с адресами/учётными данными. Скриншоты только с вымышленными данными.
Адаптеры должны использовать
штатные механизмы платформы; документация не должна объявлять их готовыми.

## Перед публикацией: обязательные решения

1. Правообладатель просматривает состав и разрешает публикацию.
2. BMS Community License 1.0 утверждена. Перед загрузкой по-прежнему нужна
   проверка прав на распространяемые компоненты; наличие NOTICE её не заменяет.
3. Проверяется отсутствие секретов и корпоративных данных в тексте,
   бинарных памятках, изображениях и архиве.
4. В [SECURITY.md](../SECURITY.md) указан разрешённый владельцем публичный
   адрес bisembi@gmail.com для конфиденциальных сообщений об уязвимостях.
5. SECURITY.md утверждён; поддерживаются все выпущенные версии 1.x без
   гарантированных сроков ответа или исправления. После создания репозитория
   требуется отдельно включить GitHub Private Vulnerability Reporting;
   сейчас настройки GitHub не менялись.
6. Решается, публикуется ли это как source candidate либо как внедряемый
   релиз после сквозной приёмки. Сейчас новая установка не принята.
7. Проверить состав дерева и ZIP, ссылки и честное описание готовности
   штатного обмена с 1С. До просмотра не публиковать.

## Как выпустить без истории разработки

После отдельного разрешения использовать **новый пустой репозиторий** и
распакованное содержимое готового исходного архива. Не копировать .git старой
разработки, резервные копии, staging и рабочие папки других агентов. Первый
коммит может содержать только один проверенный срез. Основная ветка всё
равно существует как техническая часть Git; отсутствие дополнительных
веток не отменяет main. Тег / release необязателен до решения владельца.

До фактической загрузки снова проверить manifest и архив. Не создавать
репозиторий, push или GitHub Release без нового прямого разрешения.
